# Интеграции

Параметры взяты из кода и конфигурации. Обоснования решений - в [ADR](../architecture/adr.md).

## 1. Cloud.ru Foundation Models (LLM)

Назначение: разбор запроса (/api/job) и формулировка ответа (/api/respond).

- Протокол: HTTPS, OpenAI-совместимый chat.completions.create.
- Endpoint: https://foundation-models.api.cloud.ru/v1 (CLOUDRU_BASE_URL).
- Аутентификация: API-ключ сервисного аккаунта (Key Secret) в CLOUDRU_API_KEY.
- Модель: в .env.example - ai-sage/GigaChat3.5-432B-A28B-Reasoning
- Параметры генерации: temperature 0.5, top_p 0.95, до 2500 выходных токенов.
- Таймауты: вызов 60 с, обработка /api/job - 150 с.
- Повторы: до 3 транспортных (по умолчанию 0); Retry-After дольше 5 секунд не ждётся; после невалидного ответа модели - одна исправляющая попытка.
- Ошибки нормированы кодами: model_not_configured, model_authentication_failed (401/403), model_not_available (404), model_rate_limited (429), model_request_rejected (400/422), model_unavailable (сеть, 5xx), model_timeout, job_timeout, model_invalid_output.
- Тело ошибки провайдера, ключ и prompt в публичный ответ не включаются.

/api/embed к Cloud.ru не обращается.

## 2. E5-эмбеддинги (внутри ai-service, локально)

Назначение: векторы названий записей и поисковых запросов.

- Модель: intfloat/multilingual-e5-small, ревизия зафиксирована, веса загружаются только локально с проверкой SHA256.
- Размерность: 384, L2-нормированные.
- Предобработка: NFC, обрезка пробелов; префиксы passage: и query: добавляет сервис; усечение до 512 токенов.
- Вычисление: CPU float32, один worker, два потока, срок запроса 10 с. При занятых workers - 503 без очереди; при незагруженных весах /api/embed отвечает 503, остальные ручки работают.
- Лимит тела - 16384 байта.
- Версия: model_version - хеш манифеста (e5-sha256:…); сравнивать можно только векторы одной версии.

Использование backend: при создании записи - вектор названия в task_embeddings; при поиске - вектор запроса, pgvector, cosine, порог 0.6 (не откалиброван), до 20 кандидатов, объединение с буквальным поиском.

## 3. Google Calendar

Назначение: создание новых встреч в основном календаре пользователя и проверка занятости.

- Scopes: calendar.events, calendar.events.freebusy, openid, email.
- Подключение: connect выдаёт адрес страницы согласия со state в Redis на 10 минут; после подтверждения Google возвращает браузер на callback, backend обменивает код на токены и сохраняет их в google_integrations
- Конфликты: пересечение интервала встречи (длительность GOOGLE_EVENT_DURATION, по умолчанию 1 час) с активными встречами в базе и занятостью Google; конфликт - 409, обойти нельзя.
- Таймауты и сбои: 3 с на вызов Google; ошибка проверки или синхронизации логируется и не блокирует создание записи.
- Ограничения: consent screen в режиме Testing - refresh token живёт 7 дней, затем подключение повторяется. Refresh token хранится в открытом виде.
- Выключение: без GOOGLE_CLIENT_ID и GOOGLE_CLIENT_SECRET ручки отвечают 503 google_disabled.

## 4. Email (SMTP)

Назначение: дублирование напоминаний письмом.

- Включается только при заданных SMTP_HOST и EMAIL_FROM.
- Виды писем настраиваются EMAIL_KINDS; по умолчанию все три.
- Одно письмо - до 45 с; письма отправляются последовательно, чтобы SMTP-задержки не тормозили канал уведомлений.
- Автоматических повторов нет; факт отправки фиксируется в notifications (email_sent_at).

## 5. WebSocket уведомлений

Назначение: доставка напоминаний клиенту в реальном времени.

- Endpoint: GET /api/v1/notifications/ws; Nginx проксирует с таймаутами 3600 с.
- Авторизация: первое сообщение {"type":"auth","token":...} в течение 5 секунд (в браузере нельзя задать заголовок Authorization).
- Поток сервера: ready, затем notification (сначала неподтверждённые с наступившим моментом, затем новые в своё время; порядок по created_at).
- Поток клиента: auth, затем ack на каждое уведомление; ack идемпотентен.
- Формат: один UTF-8 JSON в text frame; binary - закрытие 1003, больше 16 KiB - 1009.
- Дубликаты возможны при переподключении; клиент устраняет их по notification.id.
- Неподтверждённые хранятся 30 дней (REMINDER_RETENTION).
- Коды закрытия: 4401 (токен), 4408 (нет auth), 1003, 1009, 1008 (повторные ошибки). После 1006/1012/1013 клиент переподключается с паузой.
- Проверка соединения - стандартный WebSocket ping/pong, прикладной heartbeat не нужен.

## 6. Межсервисное взаимодействие backend ↔ ai-service

- Путь: AI_SERVICE_URL → Nginx:8091 → ai-service:8090 (закрытый контур).
- Контракт: contracts/ai.openapi.yaml; клиент сгенерирован oapi-codegen.
- Вызовы: /api/job (разбор), /api/respond (сообщение), /api/embed (векторы).
- Таймауты: SDK 60 с, job 150 с; write timeout backend 210 с, Nginx 240 с.
- Сбои: 502 (ошибка или некорректный JSON AI), 504 (таймаут), 503 (Redis или БД). Операция без подтверждённого разбора не выполняется.
- Контекст диалога хранит backend в Redis и передаёт в /api/job; ai-service к базе не обращается.
