# Диалоги `/api/task`: реплики и ожидаемое поведение

Это проверочный набор для AI-service и backend. Одинаковый смысл должен давать
одинаковый action независимо от вежливости, порядка слов и распространённых
опечаток. Модель получает исходный текст, схему JSON, локальное время и
сохранённый контекст. Backend проверяет action и выполняет его только после
валидации. В таблице "уточнить" означает HTTP 200 `needs_clarification` с
сохранённым контекстом и `task_id`.

## Самостоятельные запросы

| Реплики пользователя | Результат |
| --- | --- |
| "Привет", "Как дела?", "Спасибо", "Расскажи шутку" | `chat`, ответ без записи или чтения календаря. |
| "Что ты умеешь?" | `chat`, краткое описание поддерживаемых действий. |
| "Создай задачу купить молоко завтра", "Надо купить молоко завтра", "Добавь дело: купить молоко до конца недели" | `create_event/task`; срок без времени допустим, время не выдумывать. |
| "Напомни через час поставить пельмени на плиту", "Напомни завтра в 9 полить цветы" | `create_event/reminder` с вычисленной датой и точным временем; если время неоднозначно, уточнить. |
| "Назначь встречу с Иваном завтра в 15:00", "Запланируй созвон с Иваном на завтра, три часа дня" | `create_event/meeting`. |
| "Создай задачу завтра в 18:00", "Запланируй встречу завтра в 15:00" | Уточнить название, сохранив тип, дату и время. |
| "Создай задачу купить молоко", "Напомни полить цветы" | Уточнить дату; для напоминания также время. |
| "Встреча с Иваном завтра", "Напомни завтра вечером про отчёт" | Для встречи/напоминания уточнить точное время; не подставлять его из задачи. |
| "Встреча с Иваном 30 февраля", "Напомни вчера в 10:00" | Не создавать запись с невозможной или прошлой датой; уточнить дату. |
| "Что у меня завтра?", "Покажи все встречи", "Какие планы?", "Выведи только активные задачи" | `list_events` с названными фильтрами; без названного периода не добавлять дату и не спрашивать период. |
| "Что мне сделать в течение часа?", "А напомни, что я должен сделать в течении часа?", "Что запланировано на ближайшие 30 минут?" | `list_events` с `upcoming_minutes` 60/30 от времени запроса в часовом поясе пользователя. Это чтение списка, а не создание напоминания. |
| "Покажи завершённые задачи за неделю", "Что из встреч ещё активно?" | `list_events` с `statuses` и типом; не включать записи других состояний. |
| "Найди встречу с Таней", "Поищи дела, связанные с зубами", "Где задача AB-42?" | `search_events`: исходная тема в `query`, тип и период в отдельных полях. Не додумывать имя/название вручную. |
| "Найди записи по теме", "Поищи по названию" | Уточнить тему, без придуманного `query`. |
| "Покажи встречи с Иваном на следующей неделе" | `search_events`, имя остаётся в `query`, тип и неделя - в фильтрах. |
| "Удали встречу с Иваном", "Убери задачи на завтра" | `on_delete/find_candidates`: только поиск и показ пронумерованного списка; без удаления. |
| "Удали", "Удали какую-нибудь встречу" | Уточнить признаки конкретной записи, не выбирать запись случайно. |
| "Перенеси встречу с Иваном на завтра в 16:00", "Отметь задачу с отчётом выполненной", "Переименуй напоминание про цветы" | `on_update/find_candidates`: поиск старой записи и отдельный `changes`; ничего не менять до выбора кандидата. |
| "Измени встречу с Таней", "Перенеси на 16:00" без контекста | Уточнить соответственно изменение или признаки записи. |

## Продолжение и смена темы

| Контекст и следующая реплика | Результат |
| --- | --- |
| Спросили время встречи → "В 15:00", "в три часа", "после обеда" | Точное время завершает создание; расплывчатое время требует ещё одного уточнения. Старые название и дата сохраняются. |
| Спросили дату задачи → "Завтра", "до конца недели" | Создать задачу с сохранённым названием; время не требовать. |
| Спросили тему поиска → "Про бюджет" | Поиск с темой "бюджет" и ранее заданными типом/периодом. |
| Показали задачи → "А только активные?", "А на завтра?", "А без завершённых?" | Повторный список с новыми фильтрами и предыдущей темой, если пришёл тот же действующий `task_id`. |
| Показали встречи с Иваном → "А на следующей неделе?" | Продолжить поиск, сохранив имя Иван и тип встречи. |
| Уточняли встречу → "Нет, создай задачу купить молоко завтра" | Новая тема: старые имя, дата и тип не наследуются. |
| Уточняли встречу → "Отмени", "Не надо, ничего не создавай" | Закрыть черновик, ответить без действия; поздний ответ "в 15" не должен создавать отменённую встречу. |
| Показали кандидатов на удаление/изменение → "№2", "удали первый и третий", "все показанные" | Использовать только сохранённые показанные номера и ID этого пользователя; после проверки выполнить действие. |
| Показали кандидатов → "Да", "Наверное второй?", "№99", "второй или третий" | Не подтверждать запись; повторить список или уточнить выбор. |
| Показали кандидатов → "Нет, лучше завтра", "Найди другие", "Создай задачу..." | Обновить поиск или начать новую тему; старый набор кандидатов не использовать. |
| Удаление/изменение завершилось → "№2" | Не повторять действие: прежний выбор больше не действителен. |

## Потерянный контекст и сбои

| Условие | Результат |
| --- | --- |
| `task_id` отсутствует, полный запрос | Начать новый диалог, вернуть новый ID и обычный результат. |
| `task_id` не найден в Redis, полный запрос | Начать новый диалог с новым ID; выполнить полный запрос. |
| `task_id` не найден, пришло только "в 15:00" или "до конца недели" | Не угадывать предыдущее действие; вернуть уточнение 200 и новый ID. |
| Кэш содержит испорченный JSON/неполный контекст | Считать ID устаревшим; начать новый диалог. |
| Прислан чужой `task_id` | Ключ кэша включает `user_id`; чужой контекст не читается, выдаётся новый ID. |
| Одновременно пришли ответы с одним ID | Обработка сериализуется на время запроса; подтверждение должно использовать актуальный показанный список. |
| Модель дважды вернула JSON не по схеме | Без вызова записи в БД вернуть уточнение 200 с сохранённым ID и просьбой переформулировать. |
| Недоступен AI провайдер, Redis или БД | Не выдавать фиктивный успех; передать техническую ошибку соответствующего уровня. Уже выполненное создание нельзя превращать в ошибку из-за последующей неудачи записи истории. |
| Результат списка пуст | HTTP 200, пустая коллекция; не утверждать, что запись была создана/удалена. |
| Запись изменилась/исчезла между показом и выбором | Не удалять и не обновлять неподходящую запись; сообщить о необходимости нового поиска. |

Приоритет проверки: отсутствие нежелательной записи/удаления, сохранение
известных полей в уточнениях, корректный `task_id`, точность фильтров по
периоду и статусу, затем качество формулировки ответа. Формулировка может
меняться, действие и сохранённый контекст - нет.
