# Product Requirements Document

Требования к голосовому ассистенту для задач, напоминаний и встреч. Без пометки требование реализовано и проверяемо. Термины — в [Glossary](glossary.md).

## 1. Функциональные требования

### 1.1. Аккаунт и доступ

- FR-001. Пользователь регистрируется по имени, email, паролю (15–128 символов) и часовому поясу IANA. Email уникален без учёта регистра, пробелы по краям удаляются.
- FR-002. Пользователь входит по email и паролю и получает opaque access token сроком на 24 часа. Ошибка входа одинакова для неизвестного email и неверного пароля.
- FR-003. Операции с записями доступны только с действующим Bearer-токеном. Если user_id в запросе не совпадает с владельцем сессии, возвращается 403.
- FR-004. Выход завершает сессию токена. Повторное использование токена после выхода возвращает 401.

### 1.2. Понимание запросов

- FR-010. Ассистент принимает свободный текст и определяет действие: создать, показать список, найти, изменить, удалить запись или поддержать разговор. Заучиваемые команды отсутствуют.
- FR-011. Ассистент распознаёт относительные даты («сегодня», «завтра», «в пятницу», «через два часа», «на следующей неделе», «до конца недели») и интерпретирует их в часовом поясе пользователя.
- FR-012. Если данных не хватает, ассистент задаёт уточняющий вопрос и сохраняет черновик диалога. Ответ передаётся с тем же task_id, контекст живёт 24 часа и продлевается.
- FR-013. Дата и время не выдумываются: расплывчатое время («после обеда») требует уточнения, невозможная или прошедшая дата не сохраняется.
- FR-014. Короткая реплика без контекста («в 15:00») не интерпретируется угадыванием: ассистент просит повторить запрос целиком.
- FR-015. Вопросы «что у меня завтра?» и «какие планы?» обрабатываются как один интент списка. Период, не названный пользователем, не добавляется.
- FR-016. Запрос о ближайшем времени («что сделать в течение часа?») — чтение списка с окном, а не создание напоминания.
- FR-017. Если модель дважды вернула ответ вне схемы, ассистент просит переформулировать, не изменяя записей.
- FR-018. Светская реплика («привет») получает ответ без обращения к данным.

### 1.3. Голосовой ввод

- FR-020. Голосовой запрос принимается как WAV-файл (.wav или .wave, mono 16 kHz) до 20 MiB, распознаётся локальной моделью и обрабатывается как текстовый.
- FR-021. Ответ возвращается текстом. Голосовой ответ (TTS) не реализован.

### 1.4. Записи

- FR-030. Ассистент создаёт записи трёх типов: задача, встреча, напоминание. Записи сохраняются в PostgreSQL и доступны в последующих запросах.
- FR-031. Задача может иметь срок без точного времени. Такая запись участвует в списках и поиске по дате, но не попадает в фильтры по времени.
- FR-032. Статусы: у задачи — active, in_progress, completed; у встречи и напоминания — active, completed. Создание возвращает active, смена статуса — через диалог изменения.
- FR-033. Список записей за названный период с фильтрами по типу и статусу. Пустой результат — успешный ответ с пустым списком.
- FR-034. Поиск объединяет буквальное совпадение названия и семантический поиск (E5-векторы, pgvector). При недоступности векторного поиска буквальный продолжает работать.
- FR-035. Изменение и удаление выполняются в два шага: ассистент показывает пронумерованных кандидатов (для изменения — и предлагаемые значения), затем пользователь явно выбирает номера. Ответ «да» без номеров выбором не считается.
- FR-036. Выбор проверяется по сохранённым снимкам записей. Устаревший выбор возвращает 409 без частичного изменения или удаления. Старые номера после завершения операции действие не повторяют.
- FR-037. Выбор распознаётся словами («первый», «все показанные») и списком через запятую. Неоднозначная реплика («1.5») выбором не считается.
- FR-038. Повторяющиеся события не реализованы.

### 1.5. Встречи

- FR-040. Перед созданием встречи проверяется пересечение с активными встречами пользователя в базе и, при подключённом календаре, с занятостью Google. При конфликте встреча не создаётся: 409, время указывается в том же диалоге. Обойти конфликт подтверждением нельзя.
- FR-041. При подключённом Google Calendar новая встреча создаётся в основном календаре пользователя. Ошибка синхронизации не отменяет запись.
- FR-042. Изменение и удаление встреч с Google не синхронизируются, события из Google не импортируются (ограничение).

### 1.6. Напоминания и уведомления

- FR-050. Для активных записей с датой планируются уведомления: точный момент события и опережения 72 часа, 24 часа, 3 часа и 10 минут. Опережение планируется, только если до него больше 5 часов.
- FR-051. Запись с датой без времени уведомляется в 09:00 часового пояса пользователя; без пояса — UTC.
- FR-052. Уведомления доставляются по WebSocket после авторизации первым сообщением. Неподтверждённые досылаются при переподключении, повторный ack идемпотентен.
- FR-053. Неподтверждённые уведомления хранятся 30 дней, затем удаляются.
- FR-054. При настроенном SMTP письма отправляются по настраиваемым видам уведомлений. Email и WebSocket работают независимо.
- FR-055. Push-уведомления (мобильные, браузерные) не реализованы.

### 1.7. Интеграции

- FR-060. Пользователь подключает Google Calendar через OAuth. Статус подключения и отключение доступны через API, отключение идемпотентно.
- FR-061. Пока Google-креды не заданы, интеграционные ручки отвечают 503 google_disabled, записи создаются без календаря.
- FR-062. Read-ручка GET /api/v1/tasks возвращает список записей без запуска AI-диалога.

## 2. Нефункциональные требования

- NFR-001. Распознавание речи локальное, без внешних сервисов: GigaAM v3 CTC int8, CER не хуже 0.02, задержка не более 300 мс на реплику. Факт по бенчмарку: CER 0.0073, 241 мс.
- NFR-002. LLM-провайдер — Cloud.ru Foundation Models (GigaChat). Персональные данные не передаются иностранным сервисам (ФЗ-152/149, материалы PM).
- NFR-003. Пароли хранятся только в виде argon2id-хеша. При неизвестном email выполняется фиктивное сравнение — защита от тайминг-атак.
- NFR-004. Ответы с токенами и одноразовым state не кешируются (Cache-Control: no-store).
- NFR-005. Ошибки API возвращаются в формате Problem Details (RFC 9457) с полем code.
- NFR-006. Таймауты: запрос к БД — 3 с, вызов LLM — 60 с, обработка /api/job — 150 с, вызов Google — 3 с, письмо — 45 с.
- NFR-007. Повторный запрос с тем же user_id и task_id, пока первый обрабатывается, получает 409 conflict.
- NFR-008. Эмбеддинги воспроизводимы: сравниваются только векторы одной пары model и model_version.
- NFR-009. Rate limiting не реализован, хотя контракт описывает 429. Открытый вопрос OQ-13.
- NFR-010. Резервное копирование PostgreSQL не настроено. Открытый вопрос OQ-12.
- NFR-011. Экономика по расчётам PM (не проверялась на реальных счётчиках): COGS около 67 ₽/мес на пользователя при 100 MAU и 25 ₽ при 1000 MAU.
