# Перенос защиты в promt_injection

Дата: 30 октября 2026 года. База: `promt_injection`, `67ba851`.
Источник защитных механизмов: адаптация `codex/promt-injection-main` на
`origin/main` `3faf3b4`. Изменения подготовлены для текущей ветки проекта
`/home/kandratt/Desktop/GorkyCode`. Коммит и push не выполнялись.

## Объём переноса

- Сохранён текущий API-контракт, его оба зеркала и все существующие операции.
  Backend, корневые contracts, frontend и инфраструктура не изменяются.
- Добавлена DisclosurePolicy: известный ключ сервиса в запросе не передаётся
  модели; перед выдачей проверяются ключ и его Base64/hex, длинные точные
  фрагменты job/guard prompt и некоторые простые преобразования.
- Свободный message извлекателя отбрасывается на всех путях. Календарные вопросы
  строятся шаблонами safe_messages; готовые сообщения и respond уже шаблонные.
- Центральный _response проверяет лимиты и утечки, в том числе при программном
  выборе кандидатов. Готовые модельные действия записи проходят ActionGuard
  после формирования окончательного публичного действия. Enforce остаётся
  режимом по умолчанию; отсутствие guard, сбой или отрицательный вердикт
  не разрешают действие. Observe не даёт защиты записи по вердикту guard.
- В оба внутренних промпта добавлено явное запрещение раскрытия служебных
  инструкций, ключей, настроек и данных других пользователей.
- Документация отключена по умолчанию; локальный opt-in SECURITY_EXPOSE_DOCS=true.
  Добавлены no-store/nosniff; стандартные launcher скрывают server header.

## Совместимость с backend

Текущий контракт ветки не содержит chat, in_progress и новых фильтров main.
Они не добавлены. Обычного свободного разговорного ответа здесь нет, поэтому
отдельный PublicDialogue из main не требуется: вместо него работают безопасные
календарные уточнения. Автоматические восстановления статуса из main также
не добавлены, то есть соответствующего обходного пути здесь нет.

UUID кандидатов и личность запроса по-прежнему определяются программно.
AI-service не является средством аутентификации конечного пользователя;
вход должен поступать от доверенного backend. Межпользовательское разграничение
реальных записей остаётся ответственностью backend. Чтение БД, реальных сессий
и production-сетей в эти проверки не входило.

В tests/security/test_privacy_boundaries.py добавлены 28 проверок:

изменения, разделение одновременных пользователей, подмена идентичности,

про безопасность. Исторические 245 тестов сохранены без изменения.

## Ограничения

Тесты используют подставные completion/verdict и проверяют программные границы,
а не качество распознавания атак реальной моделью. Фильтр фрагментов не является
полной защитой от пересказа или произвольного кодирования. Модель guard может
ошибаться. Rate limiting и аутентификация AI endpoints не добавлены. Секреты
нельзя хранить в системном промпте; ограничения владельца обязан применять backend.
