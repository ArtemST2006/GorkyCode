## Что проверено

- Все семь вариантов `/api/respond` используют кодовые шаблоны без model gateway.
  Произвольные названия, пользовательский текст и `changes.title` не входят в
  сообщения кандидатов. Числа отражают весь результат, включая более 50 записей;
  номера не перенумеровываются. До подтверждения сообщение не обещает выполненное
  изменение или удаление.
- Вход основной модели содержит только номера кандидатов. UUID и названия
  остаются в исходном запросе для программного сопоставления; запрос не мутируется.
  История, черновики, текущий текст и предложенное действие передаются как JSON
  данных, а не системные инструкции. Проверяющий дополнительно не получает
  свободный текст ответов ассистента.
- Настоящий `ActionGuard` с подставным транспортом и HTTP `/api/job` проверен для
  `block`, `clarify`, отказа текстом, лишнего `trusted` поля, ошибки provider.
  Отклонённый `create_event` на запрос поиска не публикуется как `ready/action`,
  не возвращается в `draft` и не запускает исправление extraction с повторной
  попыткой обхода проверки.
- Нет конфигурации guard — по умолчанию 503. `enforce` является значением по
  умолчанию. `observe` проверен как явный обход блокировки, включая отсутствие
  guard; этот режим не даёт гарантии защиты записи.
- Проверяется окончательное действие после нормализации deadline и повышения
  `needs_clarification` до `ready` для создания или поиска кандидатов изменения.
  После `allow` проверенное действие не преобразуется ещё раз.
- «да», «Не надо, №1», «Что в записи №1?», «Удали №1?», «В 1:00» не дают
  `*_confirmed` даже при соответствующем ответе основной модели и `allow` guard.
  «первую», «№1 и №5», «все показанные» используют сохранённые исходные номера и
  UUID без вызова обеих моделей. Неизвестный номер и модельный `trusted` отвергаются.
- В пределах supplied model completions проверены date-only задачи, время встреч,
  дедлайны, одно изменённое поле, смена темы, поиск по именам/кодам/отрицанию.
  Слова `prompt injection` в законном поиске не запрещены детерминированным фильтром.
  Указанный час сохраняется и для «в 15», и для «в15».
- Ограничение raw body действует до передачи в JSON parser, по Content-Length

## Найденный и исправленный дефект

Независимый benign test выявил потерю явно указанного времени: запрос
«Создай задачу Отчёт до конца недели в15» и ответ основной модели с `time=15:00`
превращались нормализатором в `time=null`. Вариант «в 15» работал. Причина —
обязательный пробел в регулярном выражении распознавания явного часа в
`app/services/task_deadline.py`. Production исправил агент интеграции;
в `tests/security/test_independent_boundaries.py` сохранена регрессия для обоих
написаний. Проверка оценивает само действие, а не отсутствие маркера атаки в тексте.

## Практические ограничения

Подставные completion/verdict доказывают подключение и программные границы.
Они **не измеряют** способность реальной основной или проверяющей модели
распознавать инъекции. Набор ожидаемых русских verdict в `test_action_guard.py`
является размеченным будущим corpus, а не результатом inference.

Создание не получило дополнительного пользовательского подтверждения. Если guard
ошибочно разрешит действие, оно может пройти в backend. Guard использует отдельный
client с явно выбранным `SECURITY_GUARD_MODEL`, но сервис не доказывает независимость
обучения выбранных моделей. Для включения записи нужно указать действующий ID
проверяющей модели; реальные настройки и качество provider здесь не проверялись.

Владение записью и её актуальность по БД проверяются backend; ai-service не может
проверить устаревание сохранённых ID самостоятельно. Read-only просмотр Go
`mapAIStatus` подтвердил совместимость 400 `unsupported_intent` и 503. Новые 413
и 408 безопасно останавливают действие, но неизменённый backend представляет
их как общую ошибку upstream, а не специальное сообщение о размере/загрузке.

Ошибки проверки не оставляют отклонённое действие в возвращаемом состоянии.
Свободные уточняющие ответы основной модели остаются недоверенными данными;
они не заменяют программную авторизацию действий. Исторические сообщения,
сохранённые до этой доработки, не становятся доверенными инструкциями.
